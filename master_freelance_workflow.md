## The Master Workflow

| Phase | Step | What we do | Our standard process | Output |
| :--- | :--- | :--- | :--- | :--- |
| **A. Strategy** | 1 | Define market | South India → Telugu states → Hyderabad first | Target market |
| | 2 | Define niches | Use our 10 selected niches | Target niche |
| | 3 | Define services | Design Only / Design + Simple Development / Design + Advanced Development | Service path |
| **B. Prospecting** | 4 | Find businesses | Google Maps, LinkedIn, Instagram, Upwork, Contra, directories | Raw prospects |
| | 5 | Research business | Website, social media, reviews, services, competitors, activity | Research data |
| | 6 | Qualify prospect | Budget + Activity + Digital Need + Service Fit + Reachability + Credibility | Qualified prospect |
| | 7 | Score prospect | Lead score out of 100 | Priority ranking |
| | 8 | Shortlist | A/B/C priority prospects | Shortlist |
| **C. Problem Discovery** | 9 | Audit website/product | UX, UI, mobile, interaction, content, conversion, accessibility | UX/UI audit |
| | 10 | Identify business problems | Find the problems that can affect trust, usability or conversion | Problem list |
| | 11 | Identify opportunity | Map each problem to a practical design solution | Opportunity list |
| | 12 | Select service | Choose Design Only / Design + Simple Dev / Advanced | Recommended offer |
| **D. Pre-Sales Proof** | 13 | Create proof-of-value | Small redesign concept, selected screen, UX improvement, or visual direction | Proof-of-value |
| | 14 | Find decision-maker | Owner, founder, director, marketing/product decision-maker | Contact |
| **E. Outreach** | 15 | Personalized outreach | Problem → observation → solution → conversation | First message |
| | 16 | Follow-up | Follow-up based on response/no-response | Follow-up |
| | 17 | Start conversation | Understand interest and context | Initial conversation |
| **F. Discovery & Qualification** | 18 | Discovery call/chat | Business goals, users, pain points, scope, timeline, budget | Discovery notes |
| | 19 | Confirm requirements | Pages/screens, features, integrations, responsive needs, deliverables | Requirement document |
| | 20 | Confirm project fit | Check whether we can deliver it profitably and safely | Go / No-Go |
| **G. Proposal & Closing** | 21 | Define scope | Exact deliverables, exclusions and number of revisions | Scope |
| | 22 | Estimate effort | Time, complexity, resources, development needs | Effort estimate |
| | 23 | Pricing | Price according to scope + value + complexity | Project price |
| | 24 | Proposal | Problem, solution, scope, process, timeline, investment | Proposal |
| | 25 | Negotiation | Adjust scope, not blindly discount price | Agreed terms |
| | 26 | Contract | Scope, payment, revisions, ownership, timeline, cancellation | Signed contract |
| | 27 | Advance payment | Collect agreed deposit before work starts | Payment received |
| **H. Client Onboarding** | 28 | Welcome client | Explain communication, milestones and review process | Onboarding |
| | 29 | Collect assets | Brand, content, images, credentials, existing files, analytics | Asset library |
| | 30 | Kickoff | Confirm project goals and process | Kickoff confirmation |
| **I. UX Research** | 31 | Understand users | Existing users, target users, use cases | User insights |
| | 32 | Competitor research | Study direct and indirect competitors | Competitor findings |
| | 33 | Existing-product analysis | Audit current website/app/product | Current-state findings |
| | 34 | Define UX problems | Prioritize actual user/business problems | Problem statements |
| **J. UX Structure** | 35 | User flows | Map important tasks and journeys | User flows |
| | 36 | Information architecture | Sitemap, navigation, content hierarchy | IA / sitemap |
| | 37 | Wireframes | Low/mid-fidelity structure | Wireframes |
| | 38 | UX review | Validate structure before visual design | Approved UX |
| **K. UI Design** | 39 | Visual direction | Typography, color, imagery, visual language | Visual direction |
| | 40 | Design system | Components, tokens, states, spacing, typography | Design system |
| | 41 | High-fidelity design | Final responsive screens/pages | UI designs |
| | 42 | Interaction design | Hover, transition, motion, states, feedback | Interaction specification |
| | 43 | Prototype | Connect key journeys | Interactive prototype |
| **L. Design Validation** | 44 | Internal QA | Check consistency, responsiveness, accessibility, states, spacing | Internal QA |
| | 45 | Client presentation | Explain decisions and business value | Design presentation |
| | 46 | Client feedback | Collect structured feedback | Feedback list |
| | 47 | Revisions | Apply agreed changes | Revised design |
| | 48 | Final design approval | Get written approval | Approved design |
| **M. Handoff** | 49 | Prepare Figma | Organize pages, components, assets, styles | Clean Figma file |
| | 50 | Developer handoff | Explain responsive behavior, states and interactions | Handoff |
| | 51 | Documentation | Specs, components, notes, assets | Handoff documentation |
| **N. Development** | 52 | Development | Build website/product if included in contract | Functional product |
| | 53 | Integration | APIs, CMS, forms, analytics, integrations where included | Integrated product |
| | 54 | Responsive implementation | Desktop, tablet, mobile | Responsive build |
| | 55 | Design QA | Compare implementation against approved design | QA report |
| | 56 | Bug / UI fixes | Fix agreed implementation issues | Final build |
| **O. Launch & Delivery** | 57 | Final testing | Functionality, responsive, links, forms, performance, basic accessibility | Final QA |
| | 58 | Client review | Final review | Client sign-off |
| | 59 | Final corrections | Complete agreed final fixes | Final version |
| | 60 | Launch | Deploy/publish if development is included | Live product |
| | 61 | Final delivery | Figma, assets, documentation, credentials/process handoff as agreed | Final deliverables |
| | 62 | Final payment | Collect remaining amount | Payment completed |
| **P. Feedback & Proof** | 63 | Client feedback | Ask about experience and outcome | Feedback |
| | 64 | Testimonial | Request written/video testimonial | Testimonial |
| | 65 | Case study | Convert project into portfolio case study with permission | Case study |
| | 66 | Recommendation | Ask for LinkedIn recommendation/review where relevant | Social proof |
| **Q. Retention** | 67 | Referral | Ask whether they know another suitable business | Referral lead |
| | 68 | Repeat work | Identify future design/product opportunities | Next project |
| | 69 | Retainer | Offer ongoing design support when appropriate | Recurring revenue |
| **R. Internal Improvement** | 70 | Project retrospective | Review time, profit, communication, problems and wins | Project review |
| | 71 | Improve system | Update proposal, pricing, onboarding, checklists, templates | Better process |
| | 72 | Refill pipeline | Return to prospecting | Next clients |

## The three service paths inside this workflow

| Client situation | Service we sell | Where the process changes |
| :--- | :--- | :--- |
| Client already has developers | **Design Only** | Ends mainly at Design Approval + Handoff |
| Client needs a normal business/marketing website | **Design + Simple Development** | Continues through Development + Launch |
| Client needs SaaS, dashboards, payments, APIs, advanced systems | **Design + Advanced Development** | Adds technical planning, integrations, backend/external developer support |
